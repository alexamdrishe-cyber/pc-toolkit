# Сервер общего рейтинга

Принимает результаты тестов (только с согласия пользователя: модель устройства, баллы, версия теста и обезличенный
номер компьютера) и отдаёт сводные таблицы: для каждой модели — медиана по разным компьютерам, обычный диапазон
(25–75-й процентили) и что выжимают лучшие экземпляры (90-й). Каждый компьютер сначала сводится к своей медиане,
выбросы отсеиваются. «Проверенная» модель — не меньше 5 замеров с 3 разных компьютеров.

Работает в Docker на любом компьютере с Linux. Наружу выводится бесплатным туннелем [tuna.am](https://tuna.am):
белый IP, проброс портов и свой домен не нужны. Туннель ведёт только к контейнеру рейтинга — остальной компьютер
из интернета не виден.

## API

| Запрос | Что делает |
|---|---|
| `GET /health` | `{"ok":true}` — сервер жив |
| `POST /api/v1/results` | принять результат (`RatingSubmission`, до 16 КБ): 400 — неправильный, 429 — лимит на сегодня |
| `GET /api/v1/top/{cpu\|gpu\|memory\|disk}?version=N` | сводная таблица (по умолчанию — последняя версия теста) |

Лимиты: 40 результатов в день с одного компьютера и 200 — с одного адреса (адрес нигде не сохраняется).
Данные — один файл SQLite в томе `rating-data`.

## Установка

1. **tuna.am.** Зарегистрироваться, в личном кабинете:
   - «Домены» — постоянный бесплатный поддомен;
   - «API-ключи» → создать ключ с набором «Для туннелей».
2. Положить [`compose.yml`](compose.yml) в отдельную папку, рядом — файл `.env` (или те же строки в поле
   переменных вашей панели Docker):
   ```
   GITHUB_REPO=владелец/репозиторий
   TUNA_SUBDOMAIN=поддомен
   TUNA_API_KEY=ключ из личного кабинета
   ```
3. `docker compose up -d`. Первая сборка — несколько минут (скачивается .NET SDK).
4. Адрес туннеля — в журнале контейнера `tuna` (`docker compose logs tuna`): строка
   `Forwarding https://… -> rating:8080`. На бесплатном тарифе это `https://<поддомен>.a.tuna.free`.
   Проверка: `https://<поддомен>.a.tuna.free/health` → `{"ok":true}`.
5. Вписать адрес в [`pctoolkit.json`](../pctoolkit.json) в корне репозитория и отправить на GitHub:
   ```json
   { "ratingUrl": "https://<поддомен>.a.tuna.free" }
   ```
   Программа читает этот файл раз в 6 часов: если адрес когда-нибудь поменяется, достаточно поправить файл —
   новая версия программы не нужна.

**Обновить сервер:** снова `docker compose up -d` (сборка при каждом запуске; код скачивается заново, только если
в репозитории появился новый коммит).

## Проверка у себя

```
dotnet run --project server/PcToolkit.Rating
```

Данные — в папке из переменной `RATING_DATA` (в контейнере `/data`, иначе — папка `data` рядом с сервером).
Чтобы программа ходила на свой сервер, в `%LocalAppData%\PcToolkit\settings.json` впишите
`"RatingUrl": "http://адрес:порт"`. `server\run-local.cmd` запускает такой сервер с выдуманными данными для проверки экрана.
